# Values that exist on chain, and may not appear in a synthetic artifact.
#
# The rule (owner, 28 Sep 2026): **no value from a live deployment appears in any synthetic artifact,
# fixture, or page constant, ever.** It was written after E-14's demo fixture was found carrying the
# announced log's real transaction signature and slot beside a root built for the demo and published
# nowhere — and carrying them from two different publications at that. Fabricated provenance is the
# worst class of defect this repository can hold, and it is the kind an author cannot see in their own
# work.
#
# `cargo xtask gen-vectors` and `cargo xtask gen-demo` refuse to emit a file containing any value
# below, unless the pair is recorded in LIVE-VALUES.exempt. A vector that is *about* the announced
# deployment is legitimate and is exempted by name; a fixture that merely looks more concrete for
# carrying one is the defect.
#
# One value per line, then two spaces, then what it is. Hex is lowercase. Matching is
# case-insensitive, so a false positive is possible and fails generation, which is the safe direction.
#
# **This list is checked against the chain, not remembered.** Its first version was assembled by hand
# from what I could recall of the session that produced it, and it omitted **three of the six**
# signatures the deployment held at that point: epoch 20723's publication, which a review found, and
# the deploy and `initialize` transactions, which nothing had noticed. An earlier version of this note
# said two of five; a review counted and it was three of six. A list of live values built from memory
# has the same defect as a fixture built from memory, and a miscount in the note about it is the same
# defect once more.
#
# `scripts/live-values-from-chain.py` asks the cluster what touched the announced deployment and names
# anything missing here. **Run it after every publish cycle**: each adds a signature, a checkpoint
# address and a root.
#
# **What this gate cannot enforce, ruled by the owner 3 Oct 2026.** The rule above is unqualified and
# stays so, but two classes of live value cannot be held by it and are **review-enforced rather than
# gate-enforced**:
#
#   * **Bumps.** A PDA bump is 0-255. The announced deployment holds 250, 253 and 255, and 255 is also
#     the natural bump for any synthetic account because canonical search starts at 255 and counts down.
#   * **Epoch day indices.** Five digits, and a synthetic artifact may legitimately be *about* a real
#     epoch — the demo is about 20723.
#
# Listing either would make the matcher fire on unrelated text, because it matches a value as a
# case-insensitive substring of a whole file, and the exemptions that silenced the false positives are
# recorded per file **and value** rather than per occurrence — so one exemption blankets every
# occurrence in that file. That is why `check_list_shape` requires six digits or more.
#
# **So the discipline for these two classes is: a synthetic artifact uses a value no live account holds,
# and a reviewer checks it.** A review found epoch 20723's real bump, 255, in `demo/test/footprint.test.mjs`
# while both halves of the gate exited 0 (PR #57, round two, H-01); that fixture now uses 7.
#
# This is a stated boundary on enforcement, not on the rule. H-20
# ([#60](https://github.com/CertiMining/potash/issues/60)) makes the matcher token-aware so these values
# can be listed safely, and when it lands this carve-out is withdrawn. H-27 and H-28 are the two
# consequences that depend on it.
