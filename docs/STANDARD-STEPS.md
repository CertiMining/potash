# Standard steps

Every issue in this repository carries these ten steps, repeated verbatim from this file. None may be skipped.

| Step | Done means |
|---|---|
| S0 Scope and decisions | The unit's boundary is written: what is in, what is out, which files will be touched and which will not. Every decision the unit needs gets a number in `docs/DECISIONS.md` (D-03 onward; D-01 and D-02 stay in the spec's Appendix B) and is written down with its reasoning before code depends on it. A decision that changes a contract amends TCU-02 in the same pull request. No default is guessed for an unresolved field. |
| S1 Stack check | `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `Anchor.toml` once it exists, and the pinned toolchain (Rust 1.95.0, a pinned nightly for Miri, Agave 4.2.2 with platform-tools v1.54, Anchor 1.2.0) were checked before any code. Each new crate is named with its exact version, the reason for it and the alternative rejected. `Cargo.lock` changes in the same commit, and `cargo deny check` still passes. `certimining-core` stays `no_std`-compatible and uses no Solana crate outside the `solana` feature. The TS verifier's toolchain is pinned by its own decision at E-11. No framework, library or pattern the repository doesn't already use comes in without its own decision. |
| S2 Data contract | Every preimage, domain tag, Borsh layout, account layout and error code matches TCU-02 byte for byte, and changing one amends the spec first. Changing any schema-1 digest means a new schema version with its own vectors, never an edit (INV-FWD-01). Vectors come only from `cargo xtask gen-vectors`, are never edited by hand, and are committed with `vectors/MANIFEST.sha256`. Error codes never change; a new condition gets a new code. |
| S3 Reference implementation | The smallest module that proves the unit's mechanism exists and runs to exit 0 from a clean clone, before any interface is built on it. |
| S4 Tests | Known-answer and vector tests cover the unit's invariants, and every negative vector returns its documented code without panicking. Failure tests cover malformed and truncated input, missing configuration, no network and missing keys. The §4.4 privacy tests are written before the implementation for anything touching the epoch tree or what appears on-chain. Anything the program touches is tested on the Solana runtime, locally. Test counts come from the test runner, never estimated. |
| S5 Interface wired | The command, instruction or verifier call the owner uses runs the real implementation, and nothing returns fabricated data or a placeholder digest. A stub returns a fixed error and carries a loud marker. An end-to-end proof is recorded: the exact command and its output, or the transaction signature and the account bytes it wrote. |
| S6 Security baseline | The checkpoint authority, batcher key, `k_master` and QP keys live outside the repository and never appear in output, logs, chat or commits. Test keys are generated by the test and named as such. Every input is validated where it enters and fails with its documented code. No code path panics, calls unwrap or expect, indexes unchecked or uses wrapping arithmetic (INV-ERR-01); lints at the top of each crate enforce this. Every on-chain instruction checks its signer and accounts through Anchor constraints and denies by default. Limits are enforced where input is read (§1.8). Nothing that identifies an asset reaches the chain, a log or an error message. Deployments stay on localnet or devnet unless the owner decides otherwise. `cargo deny check` is clean. |
| S7 Documentation | `README.md` status, TCU-02 when the unit changed a contract, `docs/DECISIONS.md` and the unit's record in its issue are current. Every limitation is named where a reader would otherwise be misled, not only in a limitations section. No text claims fraud prevention, double-pledge prevention or regulatory compliance, and flags read as observations, never verdicts. |
| S8 Verification | The CI steps run exactly as written in a clean checkout of the final commit, printing test counts and exit codes for each group. They are `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test` for each feature set, Miri on core and log, and `cargo deny check`. The vector-manifest check joins once E-05 lands, and `anchor test` once E-08 lands. CI is green on that commit. The diff is described: files touched, added, removed and renamed. Nothing is deleted without the owner's explicit consent in the same conversation. |
| S9 Review and acceptance | Codex reviews the exact commit independently, and every finding is fixed or explicitly accepted by the owner. The issue records the evidence for each step, and the owner merges. Until then the issue says "not audited" in those words. |

## Rules

- An issue can't be closed with a standard step unchecked.
- A step that doesn't apply is marked `N/A` with a one-line reason, never deleted.
- Every step is tagged `[HUMAN]`, `[CLAUDE]` or `[CODEX]` for who does it.
- Every factual claim in an issue carries a file and line, a runnable command, or the word **unverified**.
